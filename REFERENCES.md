### Splunk, Inc. — Official Documentation (docs.splunk.com, retrieved indirectly)

- **[SPLUNK-DOCS-LICENSE-VIOLATIONS]** — "About license violations," Splunk Enterprise Admin Manual (`docs.splunk.com/en/splunk-enterprise/administer/admin-manual/10.4/manage-splunk-licenses/about-license-violations`, mirrored at the legacy path `docs.splunk.com/Documentation/Splunk/latest/Admin/Aboutlicenseviolations`). States: Enterprise license stacks licensed at 100 GB/day or higher generate warnings on exceedance but do not have search disabled; stacks licensed under 100 GB/day are in violation (search blocked, including scheduled reports/alerts; indexing continues) at 45 or more warnings in a rolling 60-day period; Trial, Dev/Test, and Developer licenses are in violation at 5 or more warnings in a rolling 30-day period (search blocked, no reset for Trial); the Free license is in violation at 3 or more warnings in a rolling 30-day period (search blocked, no reset); a license peer unreachable from the license manager for 72 hours or more is placed in violation independent of volume warnings. Page metadata observed: title "About license violations | Splunk Enterprise," breadcrumb Splunk Enterprise › Administer › Admin Manual › Manage Splunk licenses › About license violations, last-modified 2026-05-17. Retrieval note: a direct fetch of this URL returns HTTP 403 to this book's research tooling, the same constraint disclosed for every other `docs.splunk.com` reference in this file; content was instead obtained through a text-extraction fetch of the same URL, repeated across four independent passes with consistent page title/breadcrumb/last-modified metadata and consistent numbers each time, before being treated as reliable enough to cite as fact. Retrieved 2026-09-16. Cited in: Part 4 §5.
- **[SPLUNK-DOCS-HOW-LICENSING-WORKS]** — "How Splunk Enterprise licensing works," Splunk Admin Manual (`docs.splunk.com/Documentation/Splunk/latest/Admin/HowSplunklicensingworks`). States that license warnings occur when licensed daily indexing volume is exceeded, measured daily midnight-to-midnight on the license manager's system clock; that the measured volume is the raw data placed into the indexing pipeline, not the compressed size written to disk, so data filtered or dropped before indexing does not count against the license; and that Metrics data is measured the same way as event data except each metric event's size is capped at 150 bytes. Same indirect-retrieval note as `[SPLUNK-DOCS-LICENSE-VIOLATIONS]` above (direct fetch returns HTTP 403; content obtained via a text-extraction fetch of the same URL). Used as independent confirmation of the pipeline-stage measurement point this book's Part 4 §2 already stated without a direct citation. Retrieved 2026-09-16. Cited in: Part 4 §2, §5.

### Independent Academic Research (non-Splunk)

- **[AXELSSON-BASE-RATE-FALLACY]** — Stefan Axelsson, "The Base-Rate Fallacy and the Difficulty of Intrusion Detection," *ACM Transactions on Information and System Security* (now *ACM Transactions on Privacy and Security*), vol. 3, no. 3 (2000), DOI `10.1145/357830.357849` (`https://doi.org/10.1145/357830.357849`). Cited for its formal argument that, when the true (malicious) event population is a small fraction of total activity, even a detector with a low false-positive rate in isolation yields an alert stream dominated by false positives in absolute count unless detectors are aggregated or made highly selective — the academic grounding, independent of any vendor, for why aggregating several weak analytics before alerting (risk-based alerting's own mechanism) is a substantively different and sounder approach than one-match-one-notable for weak signals. Sourcing note: ACM's own hosting page (`dl.acm.org`) returned HTTP 403 to this book's fetch tooling on every retrieval attempt, the same access pattern this book's sourcing policy (`STYLE-GUIDE.md` §9.4) already discloses for `docs.splunk.com` — so this entry, like those, is not a screenshot or full-text capture of the publisher's own page. The paper's existence, title, sole author, venue, year, and DOI were independently cross-confirmed via two separate bibliographic databases queried directly by this book's research tooling: the Crossref API (`api.crossref.org`) and the Semantic Scholar API (`api.semanticscholar.org`), both retrieved 2026-09-16, with Semantic Scholar's own auto-generated summary of the paper's abstract consistent with the claim cited above. Retrieved (bibliographic confirmation) 2026-09-16. Cited in: Part 15 §1; Part 16 §5 (cross-reference).
